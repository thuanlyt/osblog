## 2026-09-05T07:30:12Z - UA-0052 (completed)

Fixed all four UA-0048 findings, scope-limited to src/server/content-contract.ts, src/server/router.ts, src/server/request.ts and tests/server (src/server/node-adapter.ts ended up untouched). (R1) `postFields.status` carried a create-only `.default('draft')`; since Zod 4's `.partial()` still applies an inner default when a key is omitted, a title-only PATCH silently injected `status: 'draft'` into the merge in content.ts, unpublishing the article, and the same synthetic field defeated the "at least one field must be updated" check on a timestamp-only PATCH. Moved the default onto `createPostInput` only via `.extend({ status: postStatusSchema.default('draft') })`, leaving the shared/partial schema's status genuinely optional-with-no-default; verified against the installed Zod (4.5.4) that omitted keys are now absent from the parsed object entirely, so `{...existing, ...input}` merges correctly retain the existing status. (R2) the cover-URL refine only pattern-matched an `https?://` prefix, so `'https://'` passed validation but crashed `new URL(...)` in the SSR document renderer; the refine now also requires `new URL(value)` to parse with a non-empty hostname. (R3) the direct `authentication().api.getSession({ headers })` call discarded Better Auth's renewed Set-Cookie on sliding-session refresh (confirmed by reading better-auth's own dispatch.mjs/types: `returnHeaders: true` returns `{ headers, response }`); `admin()` now threads a per-request `Headers` collector that both the `/api/admin/*` and SSR `/admin*` call sites populate, merged onto the final response after dispatch resolves (including on a caught error, so a renewed-but-forbidden session still gets its cookie). (R4) `boundedBody`'s over-limit branch awaited `reader.cancel()` before throwing, which for a chunked (no Content-Length) body could hang past the client's own timeout (this was the audit's reproduced defect); replaced it with a non-blocking background drain that keeps reading/discarding until the stream ends before releasing the reader lock. While building the regression test I found a second, previously-unexercised instance of the same class of bug: the declared-Content-Length-over-limit branch never touched the body at all, and on a reused keep-alive socket (Node's default agent in this runtime reuses connections) that undrained body corrupts the *next* pipelined request (~5s stall then ECONNRESET) — reproduced with an isolated throwaway script before fixing. Tried fixing it by forcing `Connection: close` in node-adapter.ts instead, but that caused an immediate client-side ECONNRESET on the request's own oversized upload (closing while the client is still mid-write); draining the same way in the background fixed both cases without touching node-adapter.ts at all. Added regression tests: tests/server/content.test.ts (schema-level, no DB) for R1/R2; tests/server/runtime.integration.test.ts (real PGlite + Better Auth) for end-to-end R1 (title-only PATCH stays published, timestamp-only PATCH rejected), R2 (malformed cover URL rejected, never persisted), and R3 (session aged past better-auth's own refresh threshold via direct SQL on the real `session` table gets a forwarded cookie on both the admin API and the SSR `/admin` page); tests/server/node-adapter.test.ts (real loopback Node HTTP server) for R4, including a same-connection follow-up request after each oversized rejection to prove the fix is a real drain and not just a closed connection.
