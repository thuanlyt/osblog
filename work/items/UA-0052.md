# Implement runtime release regressions after independent audit

## Objective

Resolve all four independently reproduced UA-0048 defects with focused regression tests and preserve current auth, SSR, SQL and request-boundary contracts.

## Acceptance criteria

- [x] Title-only PATCH preserves published status and timestamp-only PATCH is rejected; malformed cover URLs are rejected before persistence; session renewal Set-Cookie headers are forwarded on admin API and SSR paths; oversized chunked Node requests return 413 promptly; regression tests pass.

## Context to read

- `knowledge/INDEX.md`

## Plan

R1: stop `updatePostInput.partial()` from inheriting `status`'s create-only `.default('draft')` (moved the default onto `createPostInput` only). R2: require `new URL(...)` to actually parse the cover URL, not just match an `https?://` prefix. R3: call Better Auth's `getSession` with `returnHeaders: true` and forward any renewed `Set-Cookie` through a per-request `Headers` collector threaded through `admin()` and merged onto the final response in both the admin API and SSR `/admin` paths. R4: replace the blocking `await reader.cancel()` in `boundedBody`'s over-limit branch with a non-blocking background drain, and apply the same drain to the previously-untouched declared-Content-Length-over-limit branch (found via isolated repro that leaving it undrained corrupts the next request on a reused keep-alive connection).
